# 030. Consistent hashing과 노드 추가 시 키 이동량

> 캐시 키 10만 개를 노드 10대에 나눠 두고 11번째 노드를 붙였다. `hash % N`으로 나누면 90,890개(90.89%)가 다른 노드로 옮겨졌고, 가상 노드 100개짜리 해시 링에서는 9,266개(9.27%)만 옮겨졌다. 이상값은 1/11 = 9.09%다. 대신 가상 노드 없이 노드당 점 하나만 찍으면 가장 바쁜 노드가 평균의 3.72배를 받았고, 새 노드는 키를 268개만 가져갔다.

## 문제

캐시 서버나 샤드가 여러 대면 "이 키는 어느 노드에 있나"를 정해야 한다. 가장 쉬운 방법은 이렇다.

```python
node = nodes[hash(key) % len(nodes)]
```

노드 수가 그대로면 고르게 잘 나뉜다. 그런데 노드를 한 대 늘리거나 한 대가 빠지면 `len(nodes)`가 바뀌고, 대부분의 키가 다른 노드를 가리키게 된다. 캐시라면 그 키들이 한꺼번에 miss가 나서 DB로 몰린다.

Consistent hashing은 노드와 키를 같은 해시 공간(링)에 올리고, 키를 시계 방향으로 가장 가까운 노드에 둔다. 노드가 하나 늘면 그 노드 앞 구간의 키만 옮겨 간다. 얼마나 옮겨 가는지, 얼마나 고르게 나뉘는지 잰다.

## 실험

- 키 10만 개(`user:0` ~ `user:99999`), 노드 10대(`node-0` ~ `node-9`)
- 해시는 `hashlib.blake2b` 64비트, 링 조회는 `bisect`. 표준 라이브러리만 사용
- 비교: `hash % N`, 해시 링(노드당 가상 노드 1·10·100·1000개)
- 노드 추가: 10대 → 11대(`node-10`), 노드 제거: 10대 → 9대(`node-3` 빠짐)
- 옮겨진 키: 변경 전후로 담당 노드가 달라진 키 수
- 쏠림: 10대일 때 가장 많이 받은 노드 / 평균(1만 개), 가장 적게 받은 노드, 변동계수(CV, 표준편차/평균)

```bash
python3 main.py
```

## 결과

| 방식 | 노드 추가 시 옮겨진 키 | 노드 제거 시 옮겨진 키 | 최대/평균 | 최소 노드 | 최대 노드 | CV |
|---|---:|---:|---:|---:|---:|---:|

옮겨진 키가 어디로 갔나 (노드 추가)

```text
링, 가상 노드 100: 옮겨진 9,266개 전부 새 노드(node-10)로
hash % N:          옮겨진 90,890개 중 새 노드로 간 것 9,090개, 나머지 81,800개는 기존 노드끼리 자리바꿈
```

키 10만 개 조회 시간은 `hash % N` 7.7ms, 링(가상 노드 100) 27.2ms, 링(가상 노드 1000) 35.7ms였다(다시 돌린 실행에서는 8.4ms, 25.2ms, 35.8ms).

<sub>Python 3.13.12, macOS arm64. 키 배치·이동 수는 해시가 고정이라 매번 같음. 시간은 5회 중 최소값이고 실행마다 달라짐.</sub>

## 배운 점

- `hash % N`은 노드 수가 고정일 때는 가장 고르지만(CV 0.006), 노드 하나만 바꿔도 키 90%가 자리를 옮긴다. 새 노드가 받아야 할 9%만 옮기면 되는데, 나머지 81,800개는 기존 노드끼리 쓸데없이 섞였다. 캐시라면 거의 전체가 한 번에 비는 것과 같다.
- 해시 링은 옮겨지는 키를 이상값 근처(가상 노드 100개에서 9.27%)로 줄이고, **옮겨진 키는 전부 새 노드로만 간다.** 기존 노드끼리는 아무것도 바뀌지 않는다.
- 하지만 **가상 노드 없이 점 하나씩이면 링 구간 길이가 제각각이다.** 가장 바쁜 노드가 37,229개(평균의 3.72배), 가장 한가한 노드가 2,004개였다. 새 노드도 우연히 짧은 구간에 떨어져 268개만 가져갔다. 옮겨진 키가 적다고 좋은 게 아니라, 새 노드가 일을 거의 안 받은 것이다.
- 가상 노드를 늘리면 고르게 된다(최대/평균 3.72 → 1.51 → 1.14 → 1.04). 대신 링이 커져서 조회가 느려지고(이 구현에서 25~36ms/10만 건), 노드 정보도 그만큼 들고 있어야 한다.
- 노드를 뺄 때 옮겨지는 양은 **빠진 노드가 갖고 있던 양**이다. 가상 노드 100개에서 `node-3`이 마침 가장 많은 11,432개를 갖고 있어서 11.43%가 옮겨졌다. 고르게 나뉠수록 제거 때 충격도 예측하기 쉽다.
