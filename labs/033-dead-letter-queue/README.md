# 033. Dead letter queue: 독이 든 메시지가 큐를 막지 않게 하기

> 메시지 1만 건 중 129건은 몇 번을 다시 해도 처리되지 않는 poison 메시지였다. 처리 시도를 12,000번 쓸 수 있을 때, 실패한 메시지를 제자리에서 계속 재시도하면 정상 메시지가 38건만 처리됐다. 최대 3번 시도한 뒤 dead letter queue(DLQ)로 보내자 정상 메시지 9,871건이 모두 처리됐고 DLQ에는 poison 129건만 남았다.

## 문제

[021](../021-retry-backoff-jitter)에서 재시도를 다뤘다. 메시지 소비에서는 한 가지가 더 있다. 어떤 메시지는 내용 자체가 잘못돼서 몇 번을 다시 해도 처리되지 않는다. 재시도 정책이 이런 메시지를 어떻게 다루느냐에 따라 뒤에 줄 선 정상 메시지의 운명이 달라진다. 네 가지 정책을 같은 입력으로 비교한다.

## 실험

- 메시지 10,000건. 129건은 항상 오류(poison), 514건은 첫 시도만 오류이고 다시 하면 성공(일시 오류), 나머지는 정상. `random.Random(33)`으로 고정
- 소비자가 쓸 수 있는 처리 시도는 12,000번
- 제자리 무한 재시도: 성공할 때까지 그 메시지만 계속 처리
- 맨 뒤로 보내며 무한 재시도: 오류가 나면 큐 맨 뒤에 다시 넣음, 횟수 제한 없음
- 재시도 없이 바로 DLQ: 오류가 한 번 나면 DLQ로
- 최대 3번 시도 뒤 DLQ: 세 번째 오류에서 DLQ로

```bash
python3 main.py
```

## 결과

| 정책 | 쓴 시도 | 정상 처리 | 남은 큐 | DLQ | DLQ 속 정상 메시지 | poison에 쓴 시도 |
|---|---:|---:|---:|---:|---:|---:|
| 제자리 무한 재시도 | 12,000 | 38 | 9,962 | 0 | 0 | 11,960 |
| 맨 뒤로 보내며 무한 재시도 | 12,000 | 9,871 | 129 | 0 | 0 | 1,615 |
| 재시도 없이 바로 DLQ | 10,000 | 9,357 | 0 | 643 | 514 | 129 |
| 최대 3번 시도 뒤 DLQ | 10,772 | 9,871 | 0 | 129 | 0 | 387 |

<sub>Python 3.13.12, macOS arm64. 시드가 고정이라 같은 코드에서 매번 같은 수가 나옴. 오류 비율과 시도 한도는 실험용 값. 정상 메시지(일시 오류 포함)는 모두 9,871건.</sub>

## 배운 점

- 제자리 재시도는 첫 poison을 만난 순간 소비가 멈췄다. 시도 12,000번 중 11,960번이 그 메시지 하나에 쓰였다.
- 맨 뒤로 보내면 정상 메시지는 모두 처리되지만, 남은 poison 129건이 시도 한도가 끝날 때까지 계속 돌았다(1,615번). 한도가 없으면 계속 시도 횟수를 가져간다.
- 바로 DLQ로 보내면 큐는 안 막히지만 한 번 오류가 난 일시 오류 514건도 DLQ로 갔다. 사람이 DLQ를 열었을 때 정상 메시지가 섞여 있다.
- 최대 3번 뒤 DLQ는 정상 메시지를 모두 처리하고, DLQ에는 poison 129건만 남았다. poison에 쓴 시도는 387번(129건 × 3)으로 끝났다.
- DLQ는 버리는 곳이 아니라 나중에 원인을 보고 다시 넣는 곳이다. 이 실험은 DLQ에 쌓인 메시지를 다시 처리하는 흐름은 다루지 않았다.
